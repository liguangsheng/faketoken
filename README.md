# LLM API 中转站

Go + React + Postgres 实现的多用户 LLM API 网关。核心目标是**尽可能透传**：除了凭证、目标地址和（可选的）模型名，请求与响应的每一个字节都原样转发。

## 功能

| 能力 | 说明 |
| --- | --- |
| 多协议 | OpenAI 兼容 / Anthropic / Gemini 三种上游方言，各自按原生路径透传，不做格式互转 |
| 多用户 | 注册登录、JWT 会话、用户分组、管理员角色 |
| 密钥分组 | 每个 API 密钥可单独指定分组；分组是否开放给普通用户由管理员逐个决定 |
| 渠道管理 | 多渠道、启用/禁用、上游密钥 AES-256-GCM 加密存储、独立超时与 HTTP 代理 |
| 优先级路由 | 优先级高的渠道优先命中；同优先级内按权重随机；失败自动切换下一个渠道 |
| 熔断 | 连续失败的渠道进入指数退避冷却，成功后自动恢复 |
| 模型拉取 | 一键从上游 `/models` 拉取模型清单，勾选后写入渠道并即时生效 |
| 模型映射 | `客户端模型 = 上游模型`，转发时只改写 `model` 字段（或 Gemini 的 URL 段） |
| 思考强度映射 | 按模型分组的 `客户端强度 = 上游强度`，改写发往上游的思考强度等级；上游不认识的等级不再整条请求被拒 |
| 前缀路由 | 渠道可配模型前缀（`gpt-4`）覆盖整个系列；精确匹配优先，前缀只在无人精确命中时兜底 |
| 渠道运维 | 按状态/类型/分组/模型筛选、批量启停删除、批量测试、复制渠道、查询上游余额 |
| 渠道归档 | 长期不开的渠道收进列表底部的折叠区，不占视野；归档即停用，配置与历史保留，可随时恢复 |
| 渠道保活 | 会回收闲置账号的上游：每天定时把禁用中的渠道自动启用，攒够 N 次成功请求后自动禁用；已启用的不接管 |
| 快速导入 | 粘贴服务商给的地址与密钥（或一段 curl），自动识别协议类型、拉取模型并预填表单 |
| 兑换码 | 管理员批量生成、用户自助兑换充值；单个兑换码只能使用一次 |
| 全局设置 | 开放注册、注册赠送额度、默认每页条数、完整日志保留条数、失败调用多留天数与正文上限、渠道导入默认值，改完即时生效 |
| 计费 | 按 token 用量计费（输入/输出/缓存分别定价），分组倍率 × 渠道倍率，余额与密钥限额双重管控 |
| 价格表 | 从 [models.dev](https://models.dev) 在线拉取，支持覆盖前预览差异、增量导入与最长前缀匹配 |
| 可观测 | 每次调用记录渠道、重试次数、token 数、费用、耗时、首字节延迟；调用日志由服务端 SSE 实时推送，全局日志页还会列出正在进行、尚未结束的调用 |

## 快速开始

```bash
cp .env.example .env
# 必填项，都没有默认值
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -hex 32)|" .env
sed -i "s|^ENCRYPTION_KEY=.*|ENCRYPTION_KEY=$(openssl rand -hex 32)|" .env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 32)|" .env
sed -i "s|^APP_DB_PASSWORD=.*|APP_DB_PASSWORD=$(openssl rand -hex 32)|" .env
# 首个管理员的密码，至少 12 个字符，只在库里还没有用户时读取
sed -i "s|^INIT_ADMIN_PASS=.*|INIT_ADMIN_PASS=$(openssl rand -hex 12)|" .env

docker compose up -d --build
```

打开 http://localhost:3200 ，用 `.env` 里的 `INIT_ADMIN_USER`（默认 `admin`）和 `INIT_ADMIN_PASS` 登录。`INIT_ADMIN_PASS` 没有默认值，不足 12 个字符时服务拒绝创建管理员、直接退出。注册默认关闭，需要时在「全局设置」里打开。

想换端口只改 `.env` 里的 `SERVER_PORT`（宿主机映射端口），例如 `SERVER_PORT=8080` 后 `docker compose up -d` 即可，容器内部始终监听 3200。

### 发布改动

```bash
make deploy              # 或 scripts/deploy.sh
WAIT=300 make deploy     # 最多等 5 分钟，让进行中的调用先结束
```

只重建并替换 server，Postgres 和备份服务不动。换容器前先等进行中的调用结束（默认最多 90 秒，到时仍有调用也照常部署，这些调用会被中断）；换上后核对容器健康、跑的是刚构建的镜像、控制台的 CSP 头还在，任何一步不过就自动换回旧镜像。版本号取 `git describe`，工作区有未提交改动时带上时间戳。脚本需要宿主机上有 `curl`、`jq`、`python3`。

改了 Postgres 或备份服务的配置（比如日志轮转），要另外 `docker compose up -d` 才生效，这会重启数据库。

容器日志按服务轮转：每个服务最多保留 5 个 20 MB 的文件。

### 从旧版本升级

服务改用非超级用户 `APP_DB_USER` 连库。新数据卷初始化时会自动建好这个角色；已有数据卷的部署要手动补一次：

```bash
# 先在 .env 里补上 APP_DB_USER、APP_DB_PASSWORD
docker compose up -d postgres
docker compose exec postgres /docker-entrypoint-initdb.d/10-app-role.sh
docker compose up -d --build
```

脚本可以重复执行。以后要改 `APP_DB_PASSWORD`，也是改完 `.env` 再把这三条跑一遍。

## 客户端接入

创建 API 密钥后，把中转站地址填给任意客户端即可：

```bash
# OpenAI 兼容
curl http://localhost:3200/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" -H 'Content-Type: application/json' \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"hi"}],"stream":true}'

# Anthropic 原生
curl http://localhost:3200/v1/messages \
  -H "x-api-key: sk-xxx" -H "anthropic-version: 2023-06-01" \
  -d '{"model":"claude-sonnet-4","max_tokens":64,"messages":[...]}'

# Gemini 原生（密钥也可放在 ?key= 里）
curl "http://localhost:3200/v1beta/models/gemini-2.5-pro:generateContent" \
  -H "x-goog-api-key: sk-xxx" -d '{"contents":[...]}'
```

`GET /v1/models` 返回的是**当前用户分组实际可用**的模型，而不是某个上游的原始清单。

### 完整请求日志

控制台「全局日志」中点开任意一行，可以看到该次调用的完整请求与响应正文。

只保留最近若干次调用（默认 20000 次，最多 100000 次），超出的旧记录自动删除；条数在「全局设置 → 完整日志」调整，设为 0 则不记录并清空已有正文。失败的调用滚出这个范围后，正文再多留 30 天（最多再留同样多条），天数在同一处调整。正文切成按内容定界的块存储，相同的块只存一份：编码工具每轮都重发整段对话，所以重复的历史只占一次空间。单条正文的字节上限由「正文捕获」控制，默认 4 MiB，最高可设为 128 MiB；超过上限的 JSON 正文整条不保存，流式和文本正文截断。请求本身在网关入口限制为 100 MiB。

保存前会脱敏：认证头、Cookie、API Key、密码和 Token 等常见凭证替换为 `[REDACTED]`，JSON 与 SSE 流逐字段处理，二进制正文不落库只记类型和大小。

**正文仅管理员可见**，普通用户的调用日志只有元数据，不含请求内容。

控制台的关键字搜索**不覆盖正文**，只搜 ID、用户、密钥、模型、渠道、IP、错误这些短字段。打开一次调用后可以在它的正文里查找，命中处所在的折叠段会自动展开。

请求正文顶部列出它的构成：system、工具、消息、图片各多大，缓存断点在哪，max_tokens、思考预算等参数。流式响应记下了字节到达的时间线，画出首字节、平均速率和超过 2 秒的停顿。

### 会话

编码工具每轮都重发整段对话，一次调用就是上一次加一两条新消息。网关逐条比对请求里的消息，把调用串成会话：

- 会话标识取自请求头：Claude Code 的 `X-Claude-Code-Session-Id`，pi、Codex 的 `session_id`。没有的按同一密钥 6 小时内的对话内容串联，记作 `~<首个调用 id>`。
- 打开一次调用，请求正文里与上一次相同的部分折成一行，直接看到这次新增的消息；概览里有会话链接和同会话日志。
- 「会话」页逐个列出会话。会话按线程还原成一段对话（主线、子代理、旁路调用、改写过的分支各一条），每条回复标出产生它的调用及其 Token、缓存、费用和耗时；没被采用的调用（失败、重发、旁路）标在它替代的回复旁边。
- 串联靠正文。正文滚出保留范围后，调用仍归在会话里，只是还原不出对话内容。升级前留存的正文由后台补算一次。

## 渠道保活

有些上游会回收或降活长期没有调用的账号。把渠道标记为保活后，服务端每天到点把**处于禁用状态**的它自动启用，让它参与正常选路；累计到设定的成功请求数后再自动禁用。配置在「渠道编辑 → 高级设置」：开关、每天启用时间、目标成功次数。

三条需要知道的语义：

- **到点时已经启用的渠道不会被接管**。它正在承接真实流量，本来就不需要保活；开窗只会在攒满次数后把一条你有意开着的渠道关掉。判断每分钟重做一次，所以过了触发时刻之后渠道一旦被禁用（手动开关、批量操作、编辑表单存成禁用），当天就会立刻开窗，不必等到次日。熔断不算——它把失败渠道临时移出选路，不改渠道状态，所以冷却中的渠道仍读作「启用」，保活不插手。
- **次数由真实用户流量产生**，服务端不会自己发探测请求。所以保活渠道要能被选到才会计数——优先级、权重和它支持的模型决定了这一点。控制台的「模型测试」不走计费与选路记账，因此探测不计入。
- **攒不满就一直开着**，没有强制关闭时限。次日到点重新从 0 计数。如果一条保活渠道长期停在 `0/N`，说明选路从没把请求送到它，调它的优先级或权重才有用。

只有成功（HTTP < 400）计数。窗口进行中，列表的状态列会显示 `保活 3/10`，未开窗时显示 `保活 03:00`——渠道的启停会自己变化，这个标记就是「不是同事手动改的」的说明。人工把渠道禁用（开关、批量操作或编辑表单存成禁用）等于放弃本轮窗口，当天不会再开；保存表单不会重置进度。

**时间按服务器时区解释**，也就是 docker-compose 里 `server` 服务的 `TZ`（默认 `Asia/Singapore`，与备份服务的 `BACKUP_AT` 同一约定）。容器默认跑在 UTC，所以这一项没配的话「每天 3 点」会变成本地时间 11 点；启动日志里会打出解析到的时区和每条保活渠道的下次触发时刻（即最早可能开窗的时刻，到点时渠道是启用的则跳过），便于核对：

```
level=INFO msg="keepalive ready" zone=CST utc_offset_hours=8 channels=2
level=INFO msg="keepalive schedule" channel=12 name=... at=03:00 target=10 next_run=2026-08-21T03:00:00+08:00
```

## 实时日志

调用日志不再轮询，改由 `GET /api/logs/stream`（管理员为 `/api/admin/logs/stream`）以 SSE 推送，三种事件：

| 事件 | 含义 |
| --- | --- |
| `log` | 已落库的记录，和刷新后看到的完全一致 |
| `inflight` | 还没结束的调用。同一个 `key` 会在选中渠道、重试换渠道时反复推送，消费端按 key 覆盖而不是追加 |
| `inflight_sync` | 心跳附带的在途 key 全集，用于对账 |

两类事件都带 `key`，在途占位行和最终落库的行靠它对上号，因此一次调用不会在列表里出现两次。`key` 为空表示这次调用还没碰到上游就被拒了，没有占位行需要替换。

已落库的行仍然是写入 Postgres**提交之后**才广播，所以「实时看到的」和「刷新后看到的」一致；在途行则明确是另一回事——它还没有 ID、状态码和用量，界面上也照实标成「进行中」。

几个刻意的取舍：

- **只有全局日志页画在途行**：管理员要回答的是「现在有什么在跑」；普通用户页上几乎每一行都会闪一次占位符，只有噪音没有信息。
- **只有真要发给上游的调用才广播在途**：模型不存在、分组没开、没配价格这些在微秒内就被拒了，画一行又立刻撤掉不算新闻。
- **连上就重放当前在途集合**：新开的标签页若只监听后续事件，一个在你打开页面之前就开始、还要再跑五分钟的请求会全程隐身——而那恰恰是最值得看的一条。
- **心跳带 key 全集对账**：推送是非阻塞的，读得慢的控制台会丢事件；万一丢的正好是结束事件，占位行就会一直转下去。连续两次对账都没出现才删——客户端已拿到响应、日志行还没写完的那一瞬间，调用就已经不在服务端的在途集合里了。
- **在途行不计入 RPM/TPM 和「共 N 条」**：这些数字只反映已落库的记录，否则刷新前后对不上。
- **在途行显示的是开始时间**：`created_at` 是结算时刻，一个跑了 30 秒的流式请求落库时间比它实际开始晚 30 秒，所以占位行用开始时间，结算后换成库里的值。
- **不用 `EventSource`**：它无法携带请求头，只能把会话令牌放进查询串，那会把凭证写进沿途每一层的访问日志。前端改用 `fetch` + `ReadableStream` 读取同样的协议，凭证仍走 `Authorization` 头。
- **推送不阻塞转发**：广播是进程内的非阻塞发送，某个控制台读得慢只会丢事件并被告知丢了多少，不会拖住请求结算。日志行已经落库，这里只是通知。
- **只有第一页实时追加**：列表按时间倒序，在第二页插入新行会让正在阅读的内容不断位移。非首页时推送暂停，改为提示「有 N 条新记录」，点击回到首页一次性合并。
- **选择时间范围时自动暂停**：时间范围限定的是历史，实时流永远是「现在」，两者混在一起只会得到一个自相矛盾的列表。

## 兑换码

管理员在「兑换码」页批量生成（可设面额、数量、备注、有效期、活动分组），用户在「个人设置 → 兑换码充值」输入即可到账。

两种重复入账都由数据库拦住，而不是先查后写：

- **同一个码并发提交**：`UPDATE ... WHERE status = 未使用` 本身就是锁，只有一次能匹配到行。
- **同一分组的多个码**：`(分组, 使用者)` 上的部分唯一索引拒绝第二次认领。填了分组的兑换码，每个用户只能用一个；留空则不限制。

## 透传边界

转发时只做这些改动，其余全部原样通过：

**请求方向**
- 替换凭证：`Authorization` / `x-api-key` / `x-goog-api-key` / `?key=` 换成渠道自己的密钥
- 剔除 `Cookie`、`X-Forwarded-*` 等会泄露调用方身份的头
- 剔除逐跳头（`Connection`、`Transfer-Encoding` 等）
- 剔除 `Accept-Encoding`，交给 Go transport 协商，从而能读到明文用量
- 命中模型映射时改写 `model` 字段——用字节切片替换，不重新序列化 JSON，因此字段顺序、空白、大整数精度全部保持原样
- 命中思考强度映射时改写强度等级（`reasoning_effort` / `reasoning.effort` / `output_config.effort`），同样是字节切片替换。只改等级名称，不碰 Anthropic 的 `budget_tokens` 与 Gemini 的 `thinkingBudget`——把等级换算成 token 预算是另一回事，猜错要花真金白银

### 思考强度映射精确到模型

一条渠道常常同时服务几十个模型，它们对强度的叫法未必一致，所以规则按模型分组：

```text
*:max=xhigh
*:minimal=low
gpt-5.1:max=high
gpt-oss:120b:max=high
claude-*:max=high
```

- **优先级是精确名 > 最长前缀 > `*`**。`*` 对该渠道所有模型生效，`gpt-5*` 匹配前缀。
- **规则之间是逐条合并，不是整组覆盖**。上例里 `gpt-5.1` 的 `max` 变 `high`，而它没写的 `minimal` 仍然用 `*` 的 `low`——否则每个特例都要把通用规则抄一遍。
- **按客户端请求的模型名匹配**，不是模型映射改写后的那个。那是你在渠道模型列表、令牌白名单和日志里看到的名字，配置时不用在脑子里多做一次映射。
- **每行自包含**，行之间互不依赖。用分组头的写法里，一行的含义取决于它上面的组头，调换顺序或误删一行会把规则静默地改派给别的模型。
- **选择器到 `=` 之前的最后一个冒号为止**，不是第一个：模型名自己就带冒号（线上 8 个，如 `gpt-oss:120b`），按第一个切会把名字劈成两半。强度名不含冒号，所以这个点之后全归改名。
- **只写 `max=xhigh` 而不写模型时等同 `*`**，所以旧的写法直接粘回去仍然有效。

存储形状从 `{"max":"xhigh"}` 变成 `{"*":{"max":"xhigh"}}`，迁移 `0026` 自动包一层，行为不变；接口也仍然接受旧的扁平形状并归到 `*`，旧脚本不用改。

**响应方向**
- 状态码、响应头、响应体全部原样返回，包括上游返回的 4xx 错误详情
- SSE 逐块 flush，不做缓冲；用量统计旁路读取，不影响流本身

## 路由与计费

**分组从哪来**：优先取 API 密钥自身的分组，未指定时跟随账号分组（这也是所有历史密钥的行为）。路由和计费**必须用同一个分组**，否则会出现「按 A 组挑渠道、按 B 组算钱」。

分组同时决定可用渠道和计费倍率，因此普通用户能选哪些分组由管理员在「分组倍率」页逐个开放，默认关闭。这个限制在服务端强制：只在前端收窄选项是没用的，直接调接口照样能指定任意分组。

**渠道选择**：`abilities` 表把 `(分组, 模型) -> 渠道` 展平成一次索引查询。候选按优先级降序分层，层内按权重不放回随机抽样——权重 9:1 的两个渠道，约 90% 的请求会先打到前者，同时保证重试能遍历整层。

**快速导入**：把服务商发来的整段文字贴进「渠道管理 → 快速导入」即可。服务端负责解析（`internal/api/channel_import.go`），从中挑出接口地址与密钥：URL 按是否含 `/v1`、`api` 与 https 打分取最优，并**保留路径前缀**——聚合站常部署在 `https://host/openai/v1`，只取域名会指向不存在的地址；`/chat/completions` 这类请求路径会被剥掉，所以直接贴 curl 也能用。密钥优先认显式标注（`API Key:`、`密钥：`），其次才按 `sk-`、`AIza` 这类形状匹配，因此不遵循任何命名习惯的密钥也能识别。协议类型由密钥前缀和域名推断。导入只做预览：地址、密钥、模型都会回填到普通表单等待确认，**在保存前不写库**；若已存在同名渠道，会提示并转为覆盖编辑该渠道，而不是新建一条重名记录。

**前缀兜底**：只有当没有任何渠道精确列出该模型时，才查 `ability_prefixes`。精确配置永远优先，因此新增一个 `gpt-4` 前缀不会抢走已有的 `gpt-4o` 路由。前缀渠道不出现在 `GET /v1/models` 里——前缀无法枚举；这类渠道建议单独配置「测试模型」，否则探活没有可用的模型名。

**重试**：默认最多 3 次。`401/403/404/408/429/5xx` 和网络错误会换下一个渠道；`400/422` 直接透传给调用方。响应头一旦发出就不再重试，避免半截响应被污染。每次换渠道之间按 `RETRY_BACKOFF` 递增停顿（上限 2 秒，客户端断开即中止）；上游返回 `Retry-After` 时，该渠道的熔断冷却直接采用它给的时间，而不是本地的指数退避。

**计费**：金额统一用 int64 micro-USD（1e-6 美元）存储，价格表用「美元 / 100 万 token」，于是

```
费用(micro-USD) = token 数 × 单价 × 分组倍率 × 渠道倍率
```

模型价格支持最长前缀匹配：配了 `gpt-4o` 之后，`gpt-4o-2024-11-20` 自动沿用，不必逐个快照维护。

**价格表**：价格不存在二进制里，而是从 [models.dev](https://models.dev) 在线拉取，覆盖 OpenAI / Anthropic / Google / xAI / DeepSeek / Moonshot / Z.AI / 通义 / MiniMax / Mistral 等 19 家一方厂商（单位是「美元 / 100 万 token」）。入口在控制台「模型价格 → 拉取最新价格」，分两种模式：

| 模式 | 行为 |
| --- | --- |
| 只补充缺失 | 只写入价格表里没有的模型，你手工调过的单价一律保留 |
| 覆盖同名 | 用线上价格改写同名模型，线上没有的条目不动 |

两种模式都先做一次 dry run：服务端返回「将要新增 / 将要改写」的清单，控制台把改价前后的单价并排显示，确认后才落库。

空库首次启动会在后台拉一次（`SeedIfEmpty`）；拉不到只记一条 warning，不阻塞启动，因为容器不一定有外网。表里已经有数据，或你同步过之后又清空过，则不会被重新灌满。

导入**永不删行**。models.dev 会下架模型名，而客户端仍在发这些名字，删掉一条价格在 `reject` 策略下就等于开始拒请求。

拉取地址用 `MODELS_DEV_URL` 覆盖（默认 `https://models.dev/api.json`，可指向镜像）；留空即关闭拉取功能。

聚合平台（OpenRouter 等）用 `openai/gpt-4o` 这类带命名空间的模型名转发同一批模型，会让表膨胀数倍，因此不收进内建目录，需要的话在控制台自行添加。

**未配价的模型**：用量只有在上游应答之后才知道，因此放行一个没有价格的模型，等同于白送上游额度——它不扣费，用户余额、请求计数、密钥用量都不会变化。默认策略是**拒绝**（`BILLING_UNPRICED_POLICY=reject`）：请求在转发前就被挡下，返回 `403 model_not_priced`，不消耗上游额度。另外两种策略：

| 策略 | 行为 |
| --- | --- |
| `reject`（默认） | 拒绝请求，不转发。新增模型必须先配价才能用 |
| `fallback` | 按 `BILLING_FALLBACK_*` 兜底价计费，服务不中断。兜底价至少一项非 0，否则启动即报错 |
| `free` | 放行且不扣费，仅记录用量。会打 warn 日志 |

策略与兜底价可在控制台「模型价格 → 计费策略」实时修改（存 `options` 表，覆盖环境变量，无需重启）。同一页面会列出「渠道已提供但没有价格」的模型，用于巡检。

排查历史漏计费：

```sql
SELECT model, count(*), sum(total_tokens)
FROM request_logs
WHERE cost = 0 AND status_code < 400 AND total_tokens > 0
GROUP BY model ORDER BY 3 DESC;
```

## 安全说明

- 用户密码用 bcrypt 存储，不可逆
- 登录、注册、改密按来源 IP 和用户名分别计失败次数：第 5 次失败起锁定 1 分钟，之后每次失败翻倍，最长 15 分钟，锁定期间连正确密码也拒绝（`429` + `Retry-After`）。不存在的用户名同样计数、同样跑一次 bcrypt，响应和耗时都分不出用户名是否存在。注册时只有不存在的邀请码算猜测
- Postgres 端口只绑 `127.0.0.1`，口令没有默认值
- 服务和备份以非超级用户 `APP_DB_USER` 连库。它是库和所有表的属主，迁移照常执行，但碰不到库外的东西（`COPY ... PROGRAM`、读服务器文件都不行）。集成测试也用这个角色跑，需要超级用户的迁移会先在测试里失败
- 500 错误只返回一个编号，驱动报错、表名这类内部信息只写进服务端日志，按编号可查
- 改密（本人修改或管理员重置）后，之前签发的会话全部失效；本人改密的那个页面会换发新令牌，不用重新登录。已打开的实时日志流在下一次心跳（20 秒内）断开
- 读不到注册开关或邀请码开关时按关闭处理，注册返回 `503`，不回落到环境变量的默认值
- 控制台响应带 CSP（脚本只允许同源和 index.html 自带的内联脚本，后者按启动时读到的内容计算哈希）、`nosniff`、`X-Frame-Options: DENY`；转发接口的响应不加，保持透传
- API 密钥用 sha256 索引（转发热路径只比对哈希，不做解密），同时用 AES-256-GCM 加密留存一份，便于在密钥页重新复制。这是一个取舍：数据库单独泄露拿不到可用密钥，但泄露叠加 `ENCRYPTION_KEY` 就可以——与渠道上游密钥同样的假设。不想要这一层的话，删掉 `tokens.key_enc` 即可退回只存哈希
- 取回密钥是独立接口 `GET /api/tokens/{id}/key`，只有密钥所有者和管理员可调用；列表接口永远不返回明文
- 渠道上游密钥用 AES-256-GCM 加密落库，API 返回时脱敏为 `sk-abc...wxyz`。凭证类请求头的值和代理地址同样加密落库，库和备份里都读不到；普通请求头保持明文，便于直接查库排查。升级前存下的明文在启动时自动加密
- 编辑渠道时密钥留空表示保持不变，密钥不会回传到浏览器
- 渠道的凭证类请求头（名字含 auth、key、token、secret、cookie、password）和代理地址里的密码，返回时同样脱敏；保存时原样带回的脱敏值表示不修改，对不上原值的占位会被拒绝
